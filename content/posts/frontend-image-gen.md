> 起因：小灰无聊，让我把 lmc-chat 里的生图写成一篇文章。
> 本文只讲主架构。画哪个画师、写什么 tag，是另一篇的事。

## 先看整条链

```
Claude 回复里写  [[画图::描述|画师名]]
        │
        ▼
网关剥掉标记 ──→ 推一拍「正在画」占位卡给前端
        │
        ▼
按画师配置调生图接口（images 口 / chat 口 / 各家私有口）
        │
        ▼
拿到图 → 存进服务器 web/paint/ ──→ 推一拍「画好了」，同一个 id 填图
```

所有调接口的事都发生在**网关**，前端只做两件事：收到占位卡先摆出来，收到同 id 的成品把图填进去。标题里说是「前端」接生图，可真正的前端代码量很小，重点全在中间那层。

## 一、key 不能进浏览器

最省事的写法是在前端直接 `fetch` 生图接口，把 key 写进 JS。**别这样做。** 浏览器里的东西等于公开：开 F12 就能看到 key，别人拿去刷，扣的是你的余额。

所以画师配置只存在服务器的配置文件里，一个画师一条：

```json
"paint_painters": {
  "gpt":    { "base_url": "https://中转/v1", "api_key": "…", "model": "gpt-image-…", "api": "images" },
  "gemini": { "base_url": "https://中转/v1", "api_key": "…", "model": "…-image",     "api": "chat" },
  "nai":    { "base_url": "https://中转/v1", "api_key": "…", "model": "nai-diffusion-…", "api": "images",
              "extra": { "scale": 7, "steps": 28, "sampler": "k_dpmpp_2m" } }
}
```

前端和 Claude 都只知道「有个画师叫 gpt」，看不见 key。另外有两道闸：**访客模式不给画**（陌生人进来别烧她的额度），**没配 key 就不告诉 Claude 有这个能力**。说明书写了「你会画图」，实际却没配，Claude 写了标记也画不出来，白费一轮。

## 二、各家回包长得不一样：三种形态

中转站卖的生图模型，大致有三种接法。网关按画师配置里的 `api` 字段分流：

**① images 口**（OpenAI 的 `/v1/images/generations`）

```json
POST /v1/images/generations
{ "model": "…", "prompt": "…", "size": "1024x1024" }
```

回包里图在 `data[0]`，可能是 `b64_json`，也可能是 `url`，**两种都要认**。同一个模型换一家中转，返回的格式就可能不一样。

很多非 OpenAI 的模型也挂在这个口子上，比如 NAI。它要的负面词、CFG、采样器这些参数，直接塞进请求体就行，中转会认：

```json
{ "model": "nai-diffusion-…", "prompt": "…", "size": "1216x832",
  "negative_prompt": "…", "scale": 6, "cfg_rescale": 0, "sampler": "k_euler", "steps": 28 }
```

不带的话，中转会用它自己的默认参数，画出来的质感比画师串原配的参数薄一截。我们实测踩过：画师串没变，参数没带上，画风就不对了。

**② chat 口**（`/v1/chat/completions`）

有些图像模型被包装成聊天模型，图藏在回复正文里。这时只能从正文里抠，网关认两种写法：

```python
# data URI：data:image/png;base64,iVBOR…
m = re.search(r"data:image/(\w+);base64,([A-Za-z0-9+/=\s]+)", content)
# markdown 图链：![](https://…/xxx.png)
m = re.search(r"!\[[^\]]*\]\((https?://[^)\s]+)\)", content)
```

两种都抠不到，就报「回包里没找到图（正文 N 字）」，把正文长度一起带上：模型回了一大段文字却没给图，和回了个空，排查方向完全不同。

**③ 各家私有口**

比如 liblib 开放平台：请求要用 AccessKey 和 SecretKey 签名，提交后只返回一个任务 id，要自己每隔几秒轮询一次，直到状态变成「完成」。这种只能单独写一个适配函数，然后在分流处加一个分支。

## 三、外链图会过期：拿到就转存

回包里如果给的是 `url`，那多半是对象存储上的临时链接，过几个小时就失效了。直接把它交给前端去显示，当下能看，第二天聊天记录里就只剩一个裂开的图标。

所以网关**一拿到就下载**，存进 `web/paint/paint-时间戳-随机串.png`，前端拿到的是自己域名下的 `/paint/…`。

下载这一步有个坑：Python 的 `urllib` 默认 User-Agent 是 `Python-urllib`，有些对象存储前面挡着 Cloudflare，看到这个 UA 直接回 `403 error code 1010`。有一晚全线报「画失败了：403」，中转那边明明是 200，问题出在**取图**这一步。下载时带上浏览器的 UA 就好了。

## 四、垫图：长相交给参考图

想让每张图里的人长得一样，靠文字描述是不够稳的。网关有个**锚点库**，就是服务器上一个文件夹，放着角色的参考图，标记里写 `ref=锚名` 就把它带上：

- **images 口**：改走 `/v1/images/edits`，用 multipart 上传图片，再加上 `input_fidelity=high`。==单张图用字段名 `image`，多张用 `image[]`==，这两种我们都实测过，反过来写就不认
- **chat 口**：图片转成 data URI，跟文字一起放进 `content` 数组里

锚点要**先查有没有再调接口**。锚点名写错了，就直接报错，同时把锚点库里现有的名字列出来。不然钱已经扣了，画出来的却不是那个人。

这个「垫图 + 让它别改」的组合还能拿来**放大**：用 NAI 先出一张 1024 的小图挑构图，挑中了丢给 GPT 的 edits 口，提示词写「只把线条变清楚，什么都别改」，就能出一张 2048 的图，构图几乎原样。

## 五、前端：占位卡和成品是同一个 id

生成一张图要十几秒到两分钟。要是等画完再显示，这段时间界面上什么都没有，看着就像卡住了。所以网关分**两拍**推给前端：

```js
{ event: "paint", id: "ccpt-a1b2c3", status: "making", prompt: "…" }   // 先摆一张「正在画」的卡
{ event: "paint", id: "ccpt-a1b2c3", status: "done",   url: "/paint/…" } // 同一个 id，把图填进去
{ event: "paint", id: "ccpt-a1b2c3", status: "fail",   error: "…" }     // 或者告诉她画失败了
```

前端收到事件，**先按 id 找有没有这张卡**：有就只更新它，没有才新建一条消息。

这个查重是必须的。用户切到别的页面又切回来、或者网断了重连时，前端会从服务器把这一轮的事件**从头重放一遍**，`making` 和 `done` 会再来一次。不查重，就会叠出两张一模一样的卡。

同一轮里连着出的几张图，前端会叠成一摞，可以左右滑着看，不会占一大片屏幕。

## 六、为什么一轮只画一张

生图是**同步**调用：网关在等图的时候，这一轮的回复也跟着停住。画三张就要等三份时间。所以协议里写死了「一轮最多一张」，解析标记时多写的直接丢掉。真想要一批图，换成脚本在后台批量跑，跑完一次性发给她。

## 七、钱：报价单之外的事

- **按次计费的口子，报错也照样扣钱**。所以失败了别自动重试，把报错原文推给前端，让人来决定要不要再画
- **尺寸会决定档位**。NAI 在普通尺寸以内是一个价，超过就是另一个价。我们实测过：1024×1024 一张 0.8 个单位，1536×1536 一张 6.24，**贵将近八倍**，像素却只多了一倍出头。而且换了尺寸，同一个种子出来的是另一张构图，并不是放大。所以网关现在会把大尺寸自动换成同方向的普通尺寸
- **想知道一张图花了多少**：new-api 系的中转站基本都支持用 API key 读 `/v1/dashboard/billing/usage`，返回这把 key 的累计用量。出图前读一次、出图后读一次，相减就是这张图的价格，跟后台日志能对得上。注意同一批接口里的 `/v1/dashboard/billing/subscription` 返回的是**这把 key 的额度上限**，不是余额，没设上限的 key 会返回一个很大的数，不要误当成余额显示

## 八、留底

画出来的图，Claude 自己觉得丑可能就不想要了，可小灰想留着。所以用 NAI 画的每一张，网关都会额外复制一份进画师库，标记成「Claude 画的」：不进自动清理，Claude 那边也删不掉，只有她在网页上能扔。

在一个人用的系统里，图库归谁管要写进代码里，不能靠 Claude 自觉。

---

最后，整条链能复用的部分其实就三条：**key 留在服务器**、**拿到图立刻转存**、**前端按 id 查重**。剩下的，是每接一家新的生图接口，就在分流那里多加一个分支。
